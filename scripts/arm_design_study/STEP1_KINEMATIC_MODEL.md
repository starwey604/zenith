# 第一步：六轴臂、底盘与旋入卡口的运动学建模

本文件规定 `zenith/scripts/arm_design_study/` 的第一阶段代码边界。目标是给不同六轴关节布局、臂长和底盘泊位运行相同的取矿、科技核心装配与模块安装轨迹，报告**几何可行性**及失败原因。此阶段不调用 GoodArm 的 acados 求解器，不用 MuJoCo 积分动力学，也不把几何锁定判定当作实测承载能力。

## 已固定的接口方案与首个场景

接口选用「导向锥／键槽 → 直槽轴向插入 → 轴向止挡 → 旋入卡口 → 肩面阻止轴向拉脱」。旋转由六轴臂法兰提供；第一阶段只实现法兰旋转。模块与机器人末端必须具有相对运动：当前场景设**模块由工作台原有结构保持静止，六轴法兰主动对接**。工作台能否承受压入和旋转反力待实测；代码不得默认允许改造比赛场地。

前瞻手册只给出工作台与模块任务，没有卡口实际尺寸。下面的接口尺寸参数均标为 `design_assumption`，不得写成规则值。模板文件 [bayonet_interface.template.json](configs/bayonet_interface.template.json)用 `null` 表示尚未测量；求解器遇到必需的 `null` 参数必须停止，并报告缺项。示意网页仍保留多种概念，但优化目标只采用这里选定的直槽卡口。

## 坐标与路径约束

- `W`：场地世界系，长度为 m，角度为 rad；`C`：底盘定位系；`A`：六轴臂基座系；`F`：法兰系。
- `D`：模块上卡口承口的对接系。`+z_D` 从承口朝外指向机械臂，插入沿 `-z_D`。`M`：法兰上的插入件／定位件系。卡口转角按 `+z_D` 右手正向定义，方向符号和实际锁角由配置提供。
- 法兰运动链：`T_W_M = T_W_C · T_C_A · FK_6R(q) · T_F_M`。模块承口运动链：`T_W_D = T_W_module · T_module_D`。所有轨迹和锁定判定使用 `T_D_M = inv(T_W_D) · T_W_M`，不要混用法兰 TCP 与模块中心。
- 定义插入深度 `s = -translation_z(T_D_M)`：口外预接近为 `s < 0`，口面为 `s = 0`，完全压入为 `s = s_stop`。法兰绕 `+z_D` 的相对角为 `θ`；起始键槽角、旋入角及锁后允许角误差来自接口配置。
- 接触阶段底盘 `T_W_C` 固定。泊位搜索只改变动作**开始前**的 `x, y, yaw`；不得靠移动底盘修正卡口过程中的法兰路径。

法兰接口在模块侧固定时也可复用坐标链，只需交换主／承口的安装物体并检查转角方向。第一阶段以法兰插入件、模块承口为一致约定。

## 参数化几何而非动画碰撞

第一版以解析几何表示导向锥、定位键、直槽、止挡、旋转通道、锁定肩面和插入销。卡口至少按每个销的圆截面及槽道中心线／宽度检查，参数包含销数、销半径、分布圆半径、槽宽、止挡深度、旋入角、肩面覆盖量和安装公差。未知数量不填默认值。另用简单包络表示模块、腕部、连杆、工作台、底盘和任务场地障碍；模型可从简单盒／胶囊逐步替换为已核验的碰撞网格。

几何判定分四种：导向锥是否允许当前横向／倾角偏差，销是否完整地留在直槽内，止挡深度后旋转轨迹是否完整地留在周向通道内，锁定角处肩面是否几何遮挡反向轴向退出。最后一项只是**抗拉的形状代理量**，不计算强度、磨损、弹性变形或摩擦。轨迹要在槽道拐角及最小间隙处加密采样，避免离散步长跨过碰撞。

2026 任务的规则形状路径、共同 IK、粗碰撞、离台路径与显式泊位筛选已经实现；取矿可独立检查放置角样本、沿轴拔出和整矿出口余量，科技核心存矿可独立检查一、二、三级所需的不同动作。四级双核心装配不纳入存矿数据集。矿位实际位姿、出口边沿、科技核心 P／Q 轴和工具到矿石本体关系仍需测量。取矿后的底盘撤离与收臂不计入这一阶段的取矿硬条件；停车误差、网格级碰撞、收纳体积和正式候选评分仍是后续模块。当前合成路径不能作为任务成功率。

每个场景文件必须有 `scenario_id`、来源类型（`rule`／`design_assumption`／`measured`）、来源文件或实测记录、坐标系、单位和随机种子。每个运行结果必须记录机器人模型版本、接口参数版本、臂长变量、臂座安装位姿、底盘泊位及任务样本 ID。最终轨迹存逐采样的时间、底盘位姿、六关节角、法兰位姿、模块位姿、卡口 `s/θ`、碰撞余量与状态机阶段，便于后续 GoodArm 阶段读取，不要求其理解第一阶段求解器内部数据结构。

入口使用 Python，核心依赖 NumPy、SciPy；配置用标准库 JSON。模型导入辅助程序用 MuJoCo 的 `mj_forward` 读取零位坐标与关节轴、核对多个静态位姿，不进行动力学时间积分。依赖安装在 `zenith/.venv`，无需 acados、ROS 或 GoodArm 的预生成 DLL。

## 卡口轨迹状态机

| 阶段 | 法兰与模块的关系 | 进入下一阶段的判定 |
|---|---|---|
| `approach` | 模块静止，法兰从无遮挡方向接近 `D` 轴 | 整机避碰，法兰可进入导向区 |
| `cone_align` | 导向锥允许的横向和轴线偏差内 | 对中余量为正，姿态误差低于配置容差 |
| `key_align` | 保持浅插入深度，旋到键槽起始角 | 销／键与直槽对齐，尚未进入旋转通道 |
| `straight_insert` | `θ` 固定，`s` 单调增至止挡 | 全部销始终在直槽内，`s` 达止挡区间 |
| `bayonet_turn` | `s` 保持在周向通道允许区间，`θ` 单调转至锁角 | 全部销留在通道内，接口包络无穿透 |
| `locked` | 相对位姿在锁定位姿窗口 | 肩面几何阻止未解锁的轴向退出；记录为几何锁定 |
| `leave_table` | 解除工作台支撑，模块与法兰视为同一刚体 | 模块与场地、臂、底盘全程避碰 |

状态机不允许在未达到轴向止挡时开始卡口旋转，也不允许只因末端平均误差小就判为锁定。若实际接口设计需要旋后微小回退以压到肩面，将回退量作为明确的几何参数和单独阶段，不在代码中偷偷加入。

## 六轴、臂长与底盘的联合初筛

各产品模型只用作构型模板。导入后保留六根旋转轴的方向、相对位置关系及厂家关节限位；臂长变量对应各构型实际可改变的轴间距离，不能沿用 `arm_opt` 的七段同轴长度向量。记录轴 2／3／4 的平行程度、腕轴交点距离等标签，避免把不同尺寸的同一种轴关系算作不同构型。

对每个候选先枚举合法底盘泊位，再运行带关节限位的连续 IK。求解上一帧时使用前一帧关节角作主种子，另以多起点排除局部求解失败；不接受轨迹中瞬时跳到另一关节分支。再检查关节速度上界、粗碰撞、收纳及伸展包络、对接状态机和离台路径。底盘到达泊位的路线、停车误差及工作台可接近区域纳入场景；接触阶段始终锁定底盘。

同一训练／测试任务集复用于所有构型，报告每类任务完成率、最小几何余量、最差位置／姿态误差、最小关节限位余量、关节速度峰值、底盘行程和几何锁定完成率。不能把 `arm_opt` 的 5 mm 平均位置误差直接作为卡口合格标准：实际键槽和导向锥容差尚未知，须由接口配置提供。第一阶段的 `score.py` 不设力、力矩、刚度或控制稳定性通过门槛。

## 实施顺序与验收

1. 建立帧变换和参数化卡口几何。用手工指定的法兰路径验证：提前旋转被拒绝、直槽插入可通过、旋到锁角后反向直拔被肩面阻止、按解锁反向旋转后可拔出。这是第一阶段最重要的几何回归。
2. 导入 xArm6 和 UR5e 六轴模型，用厂家零位／若干已知位姿核对 FK、法兰方向、限位和构型标签；然后加入臂长参数化与统一模块接口。模型转换错误不得靠优化结果掩盖。
3. 迁移 2026 取矿及科技核心任务生成器，并生成固定任务样本。再把参数化卡口路径接到同一任务格式，先跑单一泊位，再搜索合法泊位。
4. 输出可审查的候选对照：固定构型改变臂长、固定臂长改变底盘泊位、同样尺寸约束比较不同构型。每个失败记录 `missing_input`、`parking_illegal`、`ik_failed`、`joint_limit`、`joint_jump`、`collision`、`slot_interference`、`premature_turn`、`not_locked` 等具体原因。

完成第一阶段的标准是：给定**一份明确标为假设或实测、且必需字段完整的卡口配置**，xArm6 与 UR5e 的同一组场景能重复生成轨迹和逐项失败报告；报告能区分接口几何失败、臂长可达性失败和底盘泊位失败。没有完整卡口尺寸时可以完成模型与场景构建，但不能发表「安装成功率」的定量结论。
